# Results

`results/noise_floor/train_c1_off_limit_profile.json` is a descriptive public aggregate from one local train A/A capture. It reports turn, tool-call, and generated-token distributions so `step_limit` and execute `max_tokens` can be chosen later. It is not a noise-floor pass, a protocol threshold, or a null check. `results/capability_pilot/train_spotify_capability_20.json` is the public aggregate that `scripts/evaluation/run_capability_pilot.py` wrote for the 20-task Spotify capability pilot at commit `2950555`, configuration hash `3fa2db8c…acbb`, and task-set hash `a20fe52d…3a04`. It reports zero evaluator successes. `results/spotify_capability_20_workflow.json` is the public aggregate for the `plan_progress_v1` 14B pilot at commit `a5e5c08`, configuration hash `221418b6…98c9`, and the same task-set hash. It reports zero evaluator successes, 20/20 execute-turn-cap hits, and zero `complete_task` terminations. It is a failed Stage-1 candidate, not a qualified baseline. `results/spotify_capability_20_plan_progress_v2.json` is the public aggregate for the `plan_progress_v2` 14B pilot at commit `1b9aa3b`, configuration hash `4f229b2b…bc0a`, and the same task-set hash. It reports zero evaluator successes, 11 `complete_task` terminations, and 9 execute-turn-cap hits. It is a failed Stage-1 candidate, not a qualified baseline. `results/spotify_capability_20_plan_progress_v2_interface.json` is the public aggregate for the `prompt-runtime-auth-v2` 14B pilot at commit `bab2676`, configuration hash `50324f40…d06f`, and the same task-set hash. It reports zero evaluator successes, 17 `complete_task` terminations, 3 execute-turn-cap hits, and zero parser errors. It is a failed Stage-1 candidate, not a qualified baseline. At temperature 0, tasks in one scenario repeat one trajectory, so the run is 8 scenarios, not 20 independent samples. It is not a dev baseline, a do-nothing comparison, or a harm label. `results/spotify_capability_20_sonnet_5_5.json` is the public aggregate for the Claude Sonnet 5.5 pilot on the same `prompt-runtime-auth-v2` and `plan_progress_v2` stack at commit `93ecb4a`, configuration hash `1215704a…0e57`, and the same task-set hash. It reports 14 evaluator successes in 20 attempts, 14 `appworld_completed` terminations, 6 `step_limit` failures, 10 execute-turn-cap hits, and zero runtime failures. It is the first non-zero capability result on this task set. It is a hosted-API capability reference, not the Qwen3-4B production path, not a dev baseline, and not a harm label, and the 20 tasks come from 8 scenarios, so they are clustered rather than 20 independent samples. `spotify_capability_short_v1` does not emit a 20-task set. `spotify_short_horizon_diagnostic_6` is a 6-task native capability gate on the shape-limited train pool, not a representative benchmark and not a replacement for the `spotify_capability_20` stress results. The other stage-aligned directories are still empty placeholders. `scripts/evaluation/capture_aa.py`, `validate_method.py`, `compare_plan_kl.py`, and `assess_harm_study.py` refuse to write here. `scripts/evaluation/profile_capture_limits.py` is the command that writes that public profile. `scripts/benchmark/run_lifecycle_benchmark.py` refuses checkpoint and export paths under a directory named `results`. `scripts/replay/replay_detectors.py` refuses its input and output paths the same way. `scripts/service/serve.py` refuses a store path the same way. A harness export outside that tree is not a result in `results/`. A local A/A capture, a validation summary, a supplied-sample KL error, and a planning power number are not results in this tree.

Raw artifacts and the scripts that regenerate every figure will live here. A number outside this directory is not a project result. Only the public items in `docs/DATA.md` belong here: versions and configuration hashes, split names, selection rules and seeds, scenario, task, and episode counts, task-set hashes, and aggregate statistics, confidence intervals, detector outputs, cost and latency summaries, and figures. Resolved task IDs, per-task outcomes, plans, trajectories, evaluator reports, and raw logs stay local.

- `noise_floor/`: stage 0 A/A outcome, trajectory, plan-trace KL, and batch-invariance measurements on `train` and `dev`. The one file there now is the train concurrency-1 limit profile above, not a completed noise-floor measurement.
- `capability_pilot/`: execute-mode capability pilots on fixed `train` task sets, run before a prompt or configuration is chosen for the dev baseline.
- `task_baselines/`: stage 1 production and do-nothing success on `dev`, the power calculation, and the task-mix curve.
- `validity/`: stage 2 null, coverage, reference, and KL-truncation checks.
- `release_gate/`: stage 3 `dev` harm labels, Tier 1 gate power on `train`, false blocks, gate cost, and gate-versus-harm agreement.
- `canary/`: stage 4 Tier 2 development on `dev`: rollback traces and candidate episodes served before rollback.
- `monitors/`: stage 5 Tier 3 development on `dev`: live-stream and de-duplicated alert evidence.
- `benchmark/`: stage 6 frozen `test_normal` benchmark: the shared-stream comparison and the end-to-end tier flow.
- `figures/`: outputs regenerated from the raw artifacts above.
